# Search Audit: Why Word Match (BM25) + Meaning Search Beats Vectors Alone

> [!TIP]
> **The Big Takeaway**: In AI apps, everyone hypes "vector embeddings" (semantic search). When we actually tested 25 real questions against this vault ([[40.06-ANE-Hybrid-Inference-and-Retrieval]]), **classic keyword search (BM25) crushed standalone vector search (85% vs. 40%)**—and combining both (**Hybrid RRF**) gave us the best overall balance.

---

## 1. Head-to-Head Search Results (25 Real Questions)

| Search Method | Found in Top 5 (`Recall@5`) | Speed per Search | Where It Shines (and Where It Fails) |
|---|---|---|---|
| **1. Keyword Search (BM25)** | **85.0%** | **0.85 ms** | **100% accuracy** when you type exact words (`TouchID`, `Unraid`, `SemVer 2.0`). Misses only when you use totally different words. |
| **2. Pure Vector Search (`ane-search`)** | 40.0% | 78.4 ms | Good at fuzzy concepts, but terrible at exact code names and short technical labels. |
| **3. Hybrid Search (BM25 + Vectors)** | **80.0%** | 79.2 ms | Combines both rankings so exact names AND paraphrased questions both hit the mark (see [[70.03-Why-Agent-Browsers-Fail-Comet-vs-Harnesses]]). |

---

## 2. Does Running Local Search Slow Down the Chat Model? (Zero Slowdown!)

We tested whether running 15 `ane-search` queries in the background slowed down `qwen3.5-9b-hermes-v2-oQ5e` while it was generating text in **oMLX** ([[20.03-Inference-Provider]]):
- **Chat Speed Alone**: `45.84 tokens/sec`
- **Chat Speed While Running 15 Searches**: `52.06 tokens/sec`
- **Result**: Searching the vault in the background caused **zero slowdown** to the live chat model!
