# Bug Postmortem: Why Hermes Double-Escaped JSON (And How We Fixed It)

## 1. What Went Wrong

When an AI model calls a tool, its arguments are already formatted as a JSON string (`{"key": "value"}`).
- **The Bug**: [[10.04-Hermes-Agent]]'s CLI helper was wrapping that JSON string inside *another* JSON string without unwrapping it first—turning clean settings into broken, double-slashed text (`"{\"key\": \"value\"}"`).
- **Where It Bit Us**: Running `hermes config set providers.omlx.models '[...]'` in the terminal wrote corrupted strings into `~/.hermes/config.yaml`, causing **oMLX** ([[20.03-Inference-Provider]]) to reject model requests.

---

## 2. Our Fix: Update `config.yaml` with Python Deep-Merge Instead

Instead of using `hermes config set` for lists or nested settings, we use a tiny Python script that cleanly merges new settings into `~/.hermes/config.yaml` without touching any other keys:

```python
import yaml, os, collections.abc

config_path = os.path.expanduser("~/.hermes/config.yaml")

def deep_update(base, update):
    for k, v in update.items():
        if isinstance(v, collections.abc.Mapping):
            base[k] = deep_update(base.get(k, {}), v)
        else:
            base[k] = v
    return base

with open(config_path, "r") as f:
    config = yaml.safe_load(f) or {}

# Merge new settings cleanly without double-escaping
with open(config_path, "w") as f:
    yaml.dump(config, f, default_flow_style=False, sort_keys=False)
```
