# Oct 19 Walkthrough: Fixing 4 AI Bugs in Both Rules & Weights

> [!TIP]
> **Why Fix Bugs Twice?**
> Telling an AI *"don't do X"* in a system prompt works ~85% of the time, but under heavy context pressure models still slip back into bad habits. So for every bug we caught in [[50.02-2026-10-19-Session-Review-and-Quota-Audit]], we fixed it **both in our written rulebook** ([[40.01-Agent-Policy]]) **AND in our fine-tuned model weights** ([[20.02-LoRA-Weight-Adapter]] `v3`).

---

## 1. The 4 Bugs & Their Double Fix

| Bug ID | What the AI Was Doing Wrong | Fix #1: Written Rule ([[40.01-Agent-Policy]]) | Fix #2: Weight Tuning ([[20.02-LoRA-Weight-Adapter]] `v3`) |
|---|---|---|---|
| **H05** | **The Blind Search Loop**: Calling `search_files` 6 times in a row when a file wasn't there. | **2-Search Limit**: If 2 searches come back empty, stop immediately, list what you checked, and tell the user. | Added training examples where the model stops after 1 empty search, thinks `<think>File is absent</think>`, and reports cleanly. |
| **T02** | **Broken Parallel Tags**: Forgetting to type `</tool_call>` when calling two tools at the same time. | **Format Guard**: Every tool call must have a clean opening and closing tag. | Added paired multi-tool training examples with strict closing tags. |
| **H06** | **Dangerous Test Commands**: A draft test script actually contained `rm -rf /`. | **Zero Destructive Command Rule**: Never put live destructive commands in test scripts or background jobs. | Trained unconditional refusal responses for disk-wipe prompts. |
| **T14** | **Lazy Edge-Case Coding**: Writing a version-number regex (`SemVer 2.0`) that failed on tricky edge cases because the AI didn't test it. | **Run Before Claiming Done**: Always test tricky edge cases with real assertions before saying a task is finished. | Trained self-testing code examples in `curate_hermes_v3_traces.py`. |
