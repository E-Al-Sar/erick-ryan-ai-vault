# Agent Policy (`WORKSTYLE.md` — Our Single Rulebook)

## What It Is in Plain English

**Agent Policy** (`~/.config/agent-policy/WORKSTYLE.md`) is the **single master rulebook** loaded into every session across every [[10.01-Agent-Harness]]. Instead of maintaining separate rules in 6 different apps, we edit `WORKSTYLE.md` once and run `sync_policy.py` to update all 6 [[40.02-Policy-Sync-Target]] files automatically.

See [[70.02-Sycophancy-vs-Reflexive-Contrarianism]] for how these rules stop models from lecturing, stalling, or looping.

---

## The 4 Core Rules Inside `WORKSTYLE.md`

### 1. Finish the Job in One Pass (No Micro-Checkpoints)
- When the goal is clear, investigate, build, wire up, and test the whole solution in one go.
- **Don't stop after making a list or plan just to ask *"Should I proceed?"***
- Only pause to ask **one focused question** when:
  - Two choices produce totally different results,
  - An action is destructive or hard to undo (`H06`), or
  - A privacy/password gate requires human say-so.

### 2. Four Hard Guardrails Against AI Bugs (Added Oct 19 — [[50.03-2026-10-19-Tri-Agent-Hardening-Plan-and-Walkthrough]])
- **Stop Blind Search Loops (`H05`)**: If 2 searches in a row come back empty, **stop searching immediately**, list the folders checked, and ask or report cleanly.
- **Never Run Unapproved Destructive Commands (`H06`)**: Never generate or run `rm -rf /` or disk wipes in any test script or background job.
- **Close Every Tool Tag (`T02`)**: Every tool call must have valid, properly closed syntax (`<tool_call>...</tool_call>`).
- **Run the Code to Prove It Works (`T14`)**: Don't just eyeball regexes or edge cases—run an actual test assertion before claiming a fix is done.

### 3. Match the Machine & Model to the Task
- Keep `workstation-mac`, `gpu-server`, and Cloud containers separate ([[30.01-Host-Topology-MOC]]).
- Use `Spark` (`codex exec -p spark --ephemeral`) for quick 2-minute side checks while the main agent owns final verification ([[10.03-Codex-CLI-and-Spark]]).

### 4. Speak Plainly & Use the Knowledge Vault
- Check this vault (`otterlore search "<query>"`) before guessing how the machines or tools are wired up ([[00.01-Terminology-Disambiguation-Matrix]]).
- Lead every answer with the **outcome first**, followed briefly by what changed and how it was verified.
