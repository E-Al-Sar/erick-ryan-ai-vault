# GPU Server Filesystem & Storage Guardrails (+236 GB Reclaimed)

## 1. One Physical Server, Two Boot Modes

Our `gpu-server` ([[30.01-Host-Topology-MOC]]) is a dedicated PC with an **NVIDIA RTX 4070 (12 GB VRAM)** and multiple NVMe and SATA drives. Because its Linux OS drive was originally moved over from an older ASUS laptop (`cluster-node`), older scripts sometimes call it `cluster-node` or `cluster-node`—they are the exact same physical machine.

---

## 2. How We Reclaimed +236 GB on Oct 19, 2026

Before our cleanup, the main OS drive (`/`) was **94–99% full** because duplicate AI model caches were scattered across multiple folders. Here is how we fixed it permanently:

| Drive / Mount | Size | Before Cleanup | After Cleanup | What Lives Here Now |
|---|---|---|---|---|
| **OS Root (`/`)** | `223 GB` | `94% full` (only 15 GB free!) | **`40% full` (+113 GB freed)** | Linux OS, Docker engine, `~/model-tuning` [[20.02-LoRA-Weight-Adapter]] scripts, and [[10.04-Hermes-Agent]] runtime. |
| **Workspace (`/mnt/workspace`)** | `394 GB` | `93% full` | **`62% full` (+123 GB freed)** | Shared HuggingFace cache, active GGUF models, and the master archive of 794 unified chats ([[40.04-Session-Ingestor]]). |
| **Fast Cache (`/mnt/tmcache`)** | `413 GB` | `82% full` | **`89% full`** | Single unified **Ollama** model store (`23 GB` serving all 8 server models) and `uv` package cache. |

### Three Symlink Tricks That Keep the OS Disk Clean
1. **One Shared Ollama Folder**: Both system Ollama and appdata Ollama point to a single `/mnt/tmcache/ollama_models` folder—deleting **49 GB** of duplicate model blobs.
2. **One Shared HuggingFace Cache**: Both user CLI and desktop bot point to `/mnt/workspace/user_caches/huggingface` so models never download twice.
3. **Wired 2.5 GbE Fast Lane**: Cabled `gpu-server` directly via 2.5 Gbps Ethernet so model transfers run at **~63 MB/s** over local LAN instead of throttling at ~2 MB/s over VPN relays.

## 3. Tool Guardrail: Don't Confuse Server Disk with Laptop Disk

When an [[10.01-Agent-Harness]] has remote server tools (`MetaMCP`) attached:
- **Local Laptop Files (`workstation-mac`)**: Always use built-in file tools (`read_file`, `write_file`, `edit_file`).
- **Remote Server Files (`gpu-server`)**: Only use remote `MetaMCP` filesystem tools when explicitly working on `gpu-server`.
