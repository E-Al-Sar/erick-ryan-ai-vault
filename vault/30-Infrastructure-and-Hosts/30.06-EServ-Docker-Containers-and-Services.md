# GPU Server Docker Services & Self-Healing Startup

> [!TIP]
> **Summary**: Alongside **Ollama** and [[20.02-LoRA-Weight-Adapter]] training, `gpu-server` ([[30.01-Host-Topology-MOC]]) runs self-hosted Docker stacks for photo search, browser sandboxes, local search, and voice transcription—all mounted off the OS disk so containers never fill up root storage.

---

## 1. Key Self-Hosted AI & Utility Services

| Service | Role in Our Stack | Why We Run It Locally |
|---|---|---|
| **Immich + CUDA ML** | Self-hosted photo library with GPU-accelerated face & semantic image search (`pgvector`). | Keeps personal photo indexing 100% private on the RTX 4070 GPU. |
| **Webtop Browser Sandboxes** | Full Linux desktop + browser accessible in a web tab (`KasmVNC`). | Gives background agents (like weekend job-search automation) an isolated browser that never touches personal Mac browser cookies (see `HAI-002` in [[50.04-2026-10-14-Hermes-Living-Research-Register]]). |
| **SearXNG** | Self-hosted meta-search engine. | Lets local agents run web searches with zero tracking or per-query API fees. |
| **Speaches (`faster-whisper`)** | Local speech-to-text API on GPU. | Fast voice transcription for local audio/video workflows. |
| **Portainer & Arcane** | Web dashboards for inspecting container health and logs. | Quick visual status check without SSHing into the server. |

---

## 2. Storage & Auto-Recovery Rules

1. **Keep Container Data Off the OS Drive**:
   - All databases, photo libraries, and caches live on `/mnt/workspace/` (see [[30.03-EServ-Filesystem-and-Mounts]]), keeping the 223 GB OS partition at a healthy 40%.
2. **Self-Healing Boot Script (`eserv-docker-startup.service`)**:
   - On reboot, a `systemd` service waits until Docker is ready and brings up all core stacks in order automatically.
