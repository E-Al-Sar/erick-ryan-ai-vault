# Homelab LLM Orchestration (Splitting Work Between Laptop & GPU Server)

> [!TIP]
> **Why Split Across Two Machines?**
> Running a 9B–20B model on `workstation-mac` is fast and portable, but running heavy batch jobs or training [[20.02-LoRA-Weight-Adapter]] packs at the same time would eat up the laptop's 24 GB RAM. Offloading heavy GPU work to `gpu-server` (RTX 4070 12 GB VRAM) keeps the laptop snappy.

---

## 1. Four Simple Model Tiers

| Tier | When We Use It | Brain ([[20.01-Base-Model]]) | Server ([[20.03-Inference-Provider]]) & Machine |
|---|---|---|---|
| **1. Daily Local** | Everyday agent chats, coding, and fast tagging | `Qwen3.5-9B-oQ6e` / `gpt-oss-20b` / `S1-mini` | **oMLX** on `workstation-mac` |
| **2. Heavy GPU Offload** | Multi-model councils, background jobs, and LoRA crash tests | `Qwen3.5-9B` + [[20.02-LoRA-Weight-Adapter]] (`v2`/`v3`) or `qwen2.5-coder:7b` | **Ollama** or `server_loopback.py` on `gpu-server` |
| **3. Custom GGUF Testing** | Trying out new community GGUF models | Downloaded per test | **LM Studio (`llmster`)** on `gpu-server` |
| **4. Quick Local Sandbox** | Lightweight offline prompt experiments | `Qwen 14B` / `8B` | **LM Studio** on `workstation-mac` |

---

## 2. Golden Storage Rule: Never Put Models on a RAM Disk

When `gpu-server` boots in Unraid mode (see [[30.03-EServ-Filesystem-and-Mounts]]), its root folder (`rootfs`) is a **16 GB RAM disk**.
- ✅ **Always store models on physical NVMe cache drives** (`/mnt/cache/appdata/` or `/mnt/tmcache/ollama_models/`).
- ❌ **Never let Docker or Ollama write model weights into `rootfs`**, or a single 10 GB model download will fill up system RAM and crash the server.
